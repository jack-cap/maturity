Export and analysis documentation

Schema v1 · Read-only CLI and MCP tools

Separate from the App Store app. These optional developer tools are built from the source repository. The app does not bundle, launch or register them, and they cannot access its SwiftData store, private iCloud container or other live app data. They analyse only a JSON export explicitly supplied by the user or client.

1. Create an export

In Maturity, open Settings → Export, choose a privacy mode and press Export. Exporting is user-triggered and local. The app hands the completed artifact to the macOS save panel or the iOS and iPadOS share sheet; it does not upload the artifact or select its destination.

  • Redacted is the default. Institution and account names become export-specific aliases, and user-entered free text is excluded.
  • Financial analysis aliases institution names and excludes references, notes and memos; account names remain.
  • Complete includes institution and account names, references, notes and transaction memos.

Every mode keeps the amounts, rates, dates, currencies and relationship identifiers required for accurate analysis. Review an artifact before sharing it and prefer Redacted unless readable labels are necessary. See the privacy policy for the complete disclosure.

2. Build the source tools

The source and current package instructions live in the Maturity app repository. From its root, build the Swift package with: 

swift build

The package shares the app's schema-v1 decoding and structural validation code. It does not import the app's SwiftData models or open the app container.

3. Validate or query from the command line

swift run maturity validate /path/to/export.json
cat /path/to/export.json | swift run maturity validate -

swift run maturity summary --currency AUD /path/to/export.json
swift run maturity deposits --status active --maturity-through 2027-08-30 /path/to/export.json
swift run maturity cashflows --currency AUD --date-from 2026-09-01 --is-maturity true /path/to/export.json
swift run maturity ladder --granularity month --period-through 2027-08-01 /path/to/export.json
swift run maturity liquidity --currency AUD --days 90 /path/to/export.json
swift run maturity attention --kind awaitingCollection /path/to/export.json
CommandOptional filters
summaryCurrency
depositsCurrency, deposit/account ID, status, funding, standing instruction and inclusive maturity-date range
cashflowsCurrency, deposit ID, inclusive date range and maturity flag
ladderCurrency, month/quarter granularity and inclusive period range
liquidityCurrency and an exact precomputed day horizon
attentionCurrency, item kind, deposit ID and inclusive date range

Filters on one command are combined with logical AND. Currency and UUID values are normalised, and dates must be real Gregorian YYYY-MM-DD values. A valid query with no matching rows succeeds with a row count of zero.

Results are deterministic JSON envelopes with source provenance and rows already recorded or precomputed in the export. The tools do not recalculate interest, liquidity, maturity ladders, attention items or portfolio totals, and never combine different currencies into a new total.

4. Run the read-only MCP server

swift build -c release --product maturity-mcp

The executable is .build/release/maturity-mcp. It uses MCP over standard input/output, accepts no command-line arguments and writes only protocol messages to standard output. Configure an MCP client with the executable's absolute path. For Kiro: 

{
  "mcpServers": {
    "maturity-analysis": {
      "command": "/absolute/path/to/Maturity/.build/release/maturity-mcp",
      "args": [],
      "disabled": false
    }
  }
}

Put the entry in the workspace .kiro/settings/mcp.json or user-level ~/.kiro/settings/mcp.json. The executable path lets the client start the local process; it does not give the server a path-based export API.

Available MCP tools

ToolReturns
maturity_validateSchema-v1 decoding and structural-validation result
maturity_summaryPrecomputed per-currency summaries
maturity_depositsRecorded deposit rows
maturity_cashflowsPrecomputed scheduled cashflows
maturity_ladderPrecomputed monthly or quarterly maturity periods
maturity_liquidityExact precomputed liquidity horizons
maturity_attentionPrecomputed attention items

Every call requires an export argument containing the complete JSON export as an object. Paths, URLs, JSON strings, partial exports, unknown fields and incorrect JSON types are rejected. 

{
  "export": {
    "schemaVersion": 1,
    "exportID": "...complete export continues here..."
  },
  "currency": "AUD"
}

The abbreviated object shows argument placement only; an actual call must supply every required schema-v1 field. Each compact embedded export is limited to 32 MiB. The bounded transport rejects oversized newline-delimited input before MCP decoding and admits only one request at a time.

5. Security and privacy boundary

The MCP server is stateless and exposes tools only. It provides no:

  • Export-path or URL arguments, filesystem browsing or filesystem-backed resources
  • HTTP or other network transport, exchange-rate fetching or telemetry
  • SwiftData, private CloudKit, app-container or other live-store access
  • Writes, record mutation, transaction recording or financial actions
  • Prompts, roots, sampling, elicitation or logging capabilities

It cannot create or edit deposits, collect or roll over a maturity, transfer money, send instructions to the app, enrich redacted labels or recover excluded free text. Read-only analysis of an explicitly supplied export is the final agent boundary for this release.

Before using an AI or MCP client: the local server does not upload an export by itself, but the client or its service provider receives the artifact you supply and may transmit, process, retain or log it under its own terms. Prefer a Redacted export, inspect it first and use only clients and providers you trust.

6. Current scope

Schema-v1 JSON validation, read-only CLI queries and the read-only MCP stdio server are implemented. CSV-package reading, filesystem-backed MCP resources, network transports, live-store tools and every mutation or financial-action tool are intentionally out of scope. Any future expansion requires a separate privacy and security design, explicit consent model, policy update and review before implementation.
