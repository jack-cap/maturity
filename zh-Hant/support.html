支援

適用於 iPhone、iPad 和 Mac 的 Maturity。

聯絡我們：請前往 github.com/jack-cap/maturity/issues 建立 issue。歡迎回報錯誤、詢問計算問題或提出功能需求。GitHub 會收到你提交的內容和你的 GitHub 身分，issue 也可能公開顯示。請勿張貼財務記錄或其他敏感資料。請註明你使用的裝置和 作業系統版本；若是計算問題，請使用不含敏感資訊、但足以重現該數字的代表性條件。

開始使用

  1. 設定期初餘額。輸入你現在確實可運用的現金，也就是用來存入定存之帳戶目前顯示的餘額。不要加上你已持有定存的本金。
  2. 加入你已持有的定存。每筆都要輸入實際開始日期，即使已經是幾個月前。在每筆定存中，將資金來源設為「開始追蹤前已開立」，如此便不會記錄本金的現金異動，因為這筆錢在交易帳建立前就已由銀行扣除。
  3. 查看摘要。最上方會顯示追蹤中的持倉。這個數字正好等於已記錄的自由現金（顯示為目前可用）加上未結束定存的本金，不包含應計利息、預估利息或未來利息。目前可用的金額應已與銀行相符；若不相符，請使用核對現金記錄差額。

最需要正確設定的一件事。目前可用的金額是交易記錄的總和。如果你把今天的銀行餘額 輸入為期初金額，接著又讓上週開立的定存扣除本金，同一筆錢就會被扣兩次——銀行扣一次， 應用程式再扣一次——使金額比實際少一筆本金。每筆定存的資金來源設定正是為了避免這種情況。

常見問題

Maturity 如何協助我管理滾動式定存投資組合？

先查看目前可用，了解現在可存入的金額，再把到期階梯切換為月。 階梯會顯示未來十二個月中每個月已確定將回流的本金和利息，也會顯示沒有款項的月份。 這些數字合在一起，可讓你看見今天可用的金額、日後預計回流的款項，以及到期分布中的空檔。

你可以據此規劃讓定存依序在不同月份到期，或把更多資金分配到較短期和較長期的定存。 後一種有時稱為槓鈴策略，但真正實用的資訊只是每筆金額何時可再次使用。如果一筆錢預計在 較後月份使用，不必讓它一直記錄為閒置現金：你可以把它存入較短期的定存並照常記錄， 讓該筆到期款顯示在資金再次可用的月份。

Maturity 只呈現你記錄的金額和日期；不會建議存入多少、存款期、利率或產品。 請依月度空檔和回流本金自行決定如何存放，再加入每筆定存，讓規劃保持最新。

如何加入我已持有的定存？

照常輸入每筆定存及其實際開始日期，並將資金來源設為「開始追蹤前已開立」。 因為本金在交易帳建立前就已離開帳戶，這項設定會記錄定存而不產生現金異動。 定存仍會顯示在持倉中、納入到期階梯，並在到期時存入你的現金。

如果你偏好另一種作法，也可以把期初餘額設為現金加上所有已持有定存的本金， 然後讓每筆定存照常由目前可用的現金提供資金。算出的結果相同，只是每筆定存都必須記得遵守這項規則， 任何一次疏漏都會讓金額少一筆本金。

為什麼目前可用的金額比銀行顯示的低？

幾乎都是因為你在開始追蹤前開立的定存被設為由目前可用的現金提供資金。 應用程式扣除了本金，但銀行早已扣過，因此同一筆錢少了兩次。

開啟該筆定存，將資金來源改為「開始追蹤前已開立」，然後儲存。 這會移除現金異動，使目前可用的金額增加該筆本金。如果之後數字仍不相符， 請使用核對現金記錄剩餘差額。

現金帳戶有什麼用途？

放在某家金融機構的現金不能直接為另一家金融機構的定存提供資金——必須先轉帳，而轉帳需要數天時間。 因此，「今天可以存入多少」只能依帳戶回答。帳戶也讓核對符合現實：你會逐一核對每家銀行的餘額， 而不是核對合併數字。

在摘要中開啟目前可用，即可查看帳戶和銀行明細。現金所在位置會把帳戶分組到 可收合的銀行標題下。一兩家銀行時會預設展開；銀行較多時則預設收合。每個標題會顯示帳戶數量， 而且當所有帳戶都使用同一貨幣時，會以該原始貨幣顯示可安全加總的小計。若同一家銀行包含多種貨幣， 則會顯示貨幣代碼，而不會把不同貨幣的金額相加。

應用程式要能派上用場，我需要先設定什麼？

需要四項設定；在完成前，摘要會以檢查清單顯示：

1. 你的貨幣。所有金額都依貨幣分開計算，絕不混合加總，因此這會決定新記錄的預設貨幣。 直接從檢查清單選取；若你持有多種貨幣的定存，可在設定中加入更多貨幣。

2. 你的銀行帳戶。現金存放的每個位置各設一個帳戶，因為一家銀行的現金必須先轉帳， 才能為另一家銀行的定存提供資金。在每個帳戶記錄銀行，應用程式才能將同一家銀行的帳戶分組顯示。

3. 每個帳戶的金額。為每個帳戶設定期初餘額，這是計算目前可用現金的起點。 每個帳戶都能設定，不只第一個帳戶。

4. 你已持有的定存。這是選填項目；但如果已有尚未到期的定存，加入時請把資金來源設為 開始追蹤前已開立，以免在你開始追蹤前就已離開帳戶的資金被重複扣除。

全新安裝時，這些項目會以引導流程逐步顯示，而且會一直開著，直到你離開為止， 因此不會在你輸入既有定存到一半時消失。之後，摘要中的單行提醒會指出下一個尚未完成的項目， 並可重新開啟流程。你可以在該處關閉提醒，也可以從設定再次顯示。

每個階段都是根據你的資料判定，而不是依賴儲存的旗標，因此尚未完成時不會誤稱已完成， 在第二部已同步完整投資組合的裝置上也不會重複提醒。餘額階段要求你為每個已設定的帳戶建立期初餘額， 而不只是第一個。只有貨幣和一個帳戶是必要項目；定存為選填，因為從零開始的人可能沒有既有定存。

Maturity 的應用程式預設值都已選好，你可以在設定中調整，以符合每項產品。 iCloud 不需要另外設定，也不需要手動輸入匯率。如果啟用顯示參考等值， 應用程式會依下方說明擷取公開參考匯率。

如何開啟到期提醒？

開啟設定，在通知下方啟用到期提醒。啟用時，應用程式會要求通知權限。 Maturity 會為每筆有效定存安排兩則通知：到期日前七天上午 9:00 一則，到期日上午 9:00 再一則。 通知會顯示銀行和日期，但不顯示金額。

提醒只儲存在個別裝置，因此每部想接收通知的裝置都要分別啟用。如果權限遭到封鎖， 請在系統設定中允許 Maturity 通知，再回到應用程式開啟提醒。關閉提醒時， Maturity 會從該裝置移除由它管理的通知。

如何變更應用程式語言？

開啟設定並選擇語言。保留系統預設即可跟隨裝置語言， 或選擇英文、德文、西班牙文、法文、義大利文、日文、韓文、葡萄牙文（葡萄牙）、簡體中文、 繁體中文或繁體中文（香港）。介面會立即變更。

你的選擇只套用於該部裝置，不會變更或翻譯你輸入的財務記錄。其他裝置會保留各自的語言選擇。

我可以重新排列帳戶，或按銀行分組嗎？

兩者都可以，而且分組會自動完成。在每個帳戶記錄銀行後，Maturity 會在所有顯示位置 依銀行分組——包括設定、「現金所在位置」和每個帳戶下拉式選單。同一家金融機構的帳戶永遠會相鄰， 不論加入時間多晚，因此不必在很長的清單中尋找同一家銀行的第二個帳戶。

新帳戶也會直接排在同一家銀行的其他帳戶後面，而不是加到清單最後，因此儲存順序會與畫面一致。 新增帳戶時，銀行欄位會提供你已記錄的金融機構，避免同一家銀行因不同拼法而被分成三組。

若要手動排序，請在設定中開啟帳戶選單，選擇上移或下移， 在所屬銀行內調整帳戶順序；也可選擇將 <銀行> 上移／下移來移動整個銀行群組。 銀行標題旁的箭頭也有相同作用。所有清單共用同一套排序，因此設定中的順序就是下拉式選單中的順序。 未記錄銀行的帳戶會集中在最後方的獨立標題下。

我的帳戶之間如何轉帳？

你需要輸入兩個金額：從一個帳戶轉出的金額，以及另一個帳戶實際收到的金額。 這是兩份不同帳單上的兩項獨立事實，而實際轉入的金額才代表目的帳戶真正可運用的數字。 相同貨幣的轉帳會預設讓第二個金額等於第一個，但如果入帳金額不同，仍可編輯。

因為兩端都按實際情況記錄，跨貨幣轉帳不需要匯率。輸入轉出的美元和轉入的歐元， 各帳戶餘額就會維持精確。轉帳不會改變你的總持有金額，只會改變資金所在位置， 因此不會視為支出和收入。刪除其中一端時會一併刪除兩端，因為只留下半筆轉帳會顯示資金憑空消失。

我可以追蹤多種貨幣的定存嗎？

可以。在設定中加入你使用的貨幣，並選擇一種作為預設值。每筆定存和現金異動都以一種貨幣計價， 每個金額都以該貨幣的原始單位顯示。

目前可用現金、本金、加權平均收益率和到期階梯都會依貨幣分別顯示。 精確的原始貨幣數字才是權威資料；不同貨幣絕不直接相加。核對也依帳戶和貨幣進行， 與你查看銀行帳單的方式一致。

如果不同貨幣絕不相加，我要如何比較？

摘要會以各自的原始單位列出每種貨幣的追蹤中持倉。如果貨幣超過三列，清單會收合以保持標題區精簡； 使用顯示全部和顯示較少即可展開或收合。

下方比較使用不帶貨幣單位的數字：加權平均利率、閒置現金比例，以及以天數計算的平均剩餘存款期。 長條代表比率，絕不會把不同貨幣的餘額畫在同一座標軸上。應用程式也會說明， 考量匯率變動後，某種貨幣的較高利率不一定代表換成另一種貨幣後能取得較好報酬。

我可以查看所有貨幣合併後的單一總額嗎？

可以，但只會顯示估算值，而且必須由你主動開啟。請在設定中啟用顯示參考等值。 摘要之後可能顯示完整追蹤中持倉的一個次要 ≈ 約當金額，並標示日期和參考匯率來源。

只有當所有含有追蹤中持倉的貨幣都能換算時，才會顯示這個數字。如果任何必要匯率無法取得， 就不會顯示不完整的部分換算總額。也不會另外提供換算後的目前可用現金或本金總額。 已記錄的原始貨幣數字仍是權威資料，絕不直接相加。

換算結果永遠不會儲存、不會套用至餘額，也不會用於收益率或利息數字——匯率變動不會改變你記錄的數字。 匯率是從 Frankfurter 擷取的每日公開參考匯率。實際轉帳結果會不同，因為其中不包含銀行匯率和費用。

只有啟用這項功能時，應用程式才會聯絡你個人 iCloud 以外的服務。要求中只包含貨幣代碼， 不包含投資組合金額、名稱或記錄識別碼；完整網路揭露請參閱 隱私權政策（英文）。關閉功能會刪除快取匯率。

流動性時段包含哪些日期？

每個截止點都包含當天。今天包含恰好 0 天，1 週包含恰好 7 天。 1 個月計算到從今天起一個月後的日曆日期，3 個月則計算到三個月後的日曆日期； 兩者都是按日曆月份相加，不是固定的 30 天或 90 天期間。

如果我設定兩次期初餘額，會發生什麼事？

第二次設定會取代第一次，而不是加在一起。每個帳戶只有一個期初餘額， 代表其交易記錄的起點，因此表單會告訴你目前已記錄的內容，按鈕也會顯示取代餘額。

這很重要，因為目前可用現金是整份交易記錄的總和，而不是儲存的單一數字。 如果同一帳戶有兩筆期初餘額，同一筆錢會在沒有任何畫面提示的情況下被重複計入。 若要記錄開始追蹤之後收到的款項，請改用現金流入——那是資金異動，不是起點。

我可以變更到期階梯的分組方式嗎？

可以。到期階梯可按月或季分組。預設使用季度，因為這是較精簡的呈現方式： 如果把稀疏的階梯顯示為十二個月度欄，多數畫面只會是一根長條周圍的大量空白。你的選擇會在下次啟動時保留。

每個期間只使用一根堆疊欄，同一根欄中同時顯示本金和利息，因此欄高就是該期間總額， 也能在同一處看見兩者比例。將游標指向任一期間，即可查看精確的本金、利息和付款金融機構。

為什麼貨幣符號會包含英文字母？

裝置地區設定會影響貨幣符號的顯示方式。當符號可能混淆時，系統可能加入字母來區別， 例如顯示 US$ 或 HK$，而不只顯示 $。如果希望系統在支援時顯示單純符號， 請將裝置地區設為與主要貨幣相符。

利息如何計算？

Maturity 預設使用 actual/365 日數計算基準。每筆定存也可選擇 actual/360 和 30/360， 以符合產品報價採用的慣例。利息會在每個計息期間結束時四捨五入到最接近的分， 這與銀行作法相同，因此定期付息定存的總額可能會與整段存款期一次計算的結果相差一兩分。

應用程式的數字和銀行不符，哪一個才正確？

以銀行為準。正因如此，Maturity 中每個計算出的數字都能編輯——請尋找使用銀行報價金額的選項。 小幅差異常見原因包括日數計算基準不同、利息從存入隔天而不是當天起算，或銀行在不同計算階段進行四捨五入。 輸入實際數字後，應用程式就會記錄該金額。

提前解約如何運作？

各家金融機構的條件不同。有些會減少利息，或要求在撥付款項前先經過通知期。 Maturity 會將通知和結算記錄為不同階段，讓這段間隔期間的現金預測保持準確，並估算減少後的利息。 以金融機構報價為準；取得報價後，請輸入該數字。

定存續存時會發生什麼事？

請使用續存，而不是先收回再重新存入。這項功能會結束舊定存、開立新定存並記錄兩端， 因此交易記錄會顯示資金從未經過日常使用的帳戶。你可以續存部分到期款，並把其餘款項保留為現金； 想把利息當作收入、只續存本金時，常會這樣處理。新利率會刻意留白， 因為銀行會採用續存當日的現行利率，而不是舊利率。

為什麼應用程式要我確認利息付款？

對於按月或按季付息的定存，應用程式知道利息何時應付，但不會自行寫入你的交易帳。 把未確認的數字放進記錄會妨礙核對，並留下你從未檢查的金額。因此，摘要畫面會提示你， 讓你一鍵接受，或先修改金額再確認。

我的裝置沒有同步。

請確認兩部裝置登入同一個 Apple 帳號、已開啟 iCloud 雲碟，而且 iCloud 設定中已啟用 Maturity。 同步需要網路連線，也可能需要一點時間才能完成。通常在兩部裝置上把應用程式切換到前景， 就會促使它們交換資料。如果裝置完全沒有 iCloud 帳號，應用程式仍可使用，並將資料保存在本機。

我的資料有備份嗎？

如果已開啟 iCloud 同步，你的記錄會同時存在私人 iCloud 容器和每部裝置上， 因此遺失一部裝置不會讓資料一併遺失。但這不能取代經過審慎規劃的備份策略。 開發者並沒有投資組合的應用程式內副本，無法代你復原。你自願透過 GitHub 提交的支援內容是另一回事， 開發者和大眾都可能看見該內容。

可以自動連接我的銀行嗎？

不行，這是刻意的設計。Maturity 永遠不會要求銀行登入資料，也不會聯絡金融機構。 所有資料都由你手動輸入，因此沒有登入憑證可能外洩，也沒有第三方介於你和銀行之間。

刪除定存會改變我的現金餘額嗎？

預設不會。刪除定存時，其現金異動會保留在交易帳中，因此自由現金不受影響——移除一筆記錄不應默默改寫現金歷史。 如果只是清除誤輸的項目，請選擇同時刪除定存及其記錄的選項。

回報計算問題

利息計算尤其需要正確，因此特別歡迎這類回報。請提供：

  • 本金、利率、開始日期和到期日
  • 利息付款頻率，以及你選擇的日數計算基準
  • 應用程式顯示的數字，以及銀行提供的數字
